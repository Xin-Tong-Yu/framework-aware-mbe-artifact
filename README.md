# Framework-Aware Search-State Optimization for Maximal Biclique Enumeration

Experimental artifact for reproducing the maximal biclique enumeration comparisons and ablation studies in the associated paper.

This repository provides **experiment source code, thirteen cleaned bipartite graph inputs, reproducibility scripts, and integrity manifests**. Benchmark outputs are generated by the scripts and written locally; the repository does not distribute machine-specific timing logs or per-run output CSVs.

## Repository contents

| Path | Purpose |
|---|---|
| `src/fair_mbet/`, `runners/MBE_FAIR_MBET_2024.zip` | Four-mode MBET, MBETM, Single ST-noCR, and Single ST+CR comparison |
| `src/pure_et1_et2/`, `runners/MBE_PURE_ET1_ET2.zip` | Unguided Single/Double ST, ET1, ET2 comparison |
| `src/paper_ablations/` | Candidate Tree, Result Tree/CR, Double state, termination guidance, and IPS baseline source bundle and study descriptions |
| `scripts/` | Data reconstruction, integrity checking, campaign entry points, and output validation |
| `data/parts/` | Six contiguous parts of the canonical cleaned-graph archive |
| `data/COLLECTED_INPUT_SHA256.csv` | Per-graph input SHA-256 and byte-size manifest |
| `data/GRAPH_STATISTICS.csv` | Graph vertex, edge, and maximum-degree statistics |
| `EXPERIMENT_COVERAGE.md` | Study-to-command mapping and timing/output protocol notes |
| `SOURCE_ATTRIBUTION.md` | Third-party algorithm and dataset provenance |

## Requirements

Linux or WSL2; Python 3.9 or later; GCC/G++ with C++17 support; CMake; Bash; and standard Unix utilities. The reference environment used Ubuntu 24.04 and GCC 13.3.0. Experiments use single-threaded execution. Runtime and memory usage depend on the input graph and machine; allow sufficient RAM and disk space. The pure-biplex BibSonomy campaign uses a 256 MiB stack allowance in its launcher.

## 1. Prepare and verify the thirteen graph inputs

From the repository root:

```bash
python3 scripts/prepare_data.py
python3 scripts/verify_artifact.py --full-scan
python3 scripts/check_release.py
```

`prepare_data.py` validates all six committed archive parts, reconstructs the canonical archive, and extracts `data_clean/*.txt`. Each restored file is checked against the manifest SHA-256. The `--full-scan` option additionally validates edge counts and vertex ID ranges.

The first line of each graph is **metadata** (`nL nR m`), not a graph edge. Remaining lines contain two-column bipartite edges. The algorithms use this header-aware input contract.

The reconstructed archive, extracted graphs, local outputs, and build caches are excluded from version control.

## 2. Validate code paths on small graphs

```bash
python3 runners/MBE_FAIR_MBET_2024.zip selftest --cases 20

python3 runners/MBE_PURE_ET1_ET2.zip selftest --cases 20 \
  --modes single_st,single_et1,single_et2,double_compact_st,double_compact_et1,double_compact_et2

python3 scripts/setup_paper_ablations.py --check-only
python3 scripts/setup_paper_ablations.py
bash scripts/run_paper_ablations.sh check-source
```

The source-only archive `src/paper_ablations/MBE_PAPER_ABLATIONS_FINAL_SOURCE_BUNDLE.zip` contains the additional study modules. The installer verifies its pinned checksum, extracts it under `outputs/paper_suite/framework_ablations/`, and connects the restored inputs. It does not run enumeration experiments during installation.

For a native small-graph oracle comparison in the expanded suite:

```bash
bash scripts/run_paper_ablations.sh oracle 20
```

## 3. Run the four-mode MBET comparison

```bash
mkdir -p outputs

python3 runners/MBE_FAIR_MBET_2024.zip bench data_clean/youtube.txt \
  --modes mbet,mbetm,st_nocr,st_cr \
  --repeats 5 --out outputs/youtube_fair.csv
```

To run the thirteen-graph batch with saved progress:

```bash
python3 runners/MBE_FAIR_MBET_2024.zip batch \
  --data-dir data_clean \
  --modes mbet,mbetm,st_nocr,st_cr \
  --repeats 5 --timeout 7200 \
  --out-dir outputs/fair_13 --resume
```

The four modes use aligned count and order-independent XOR/SUM fingerprints; disk tuple writing is disabled in the benchmark configuration.

## 4. Run the unguided ET1/ET2 ablation

```bash
mkdir -p outputs/pure_13

python3 runners/MBE_PURE_ET1_ET2.zip all data_clean/youtube.txt \
  --modes pure --repeats 5 --out outputs/pure_13/youtube.csv

python3 scripts/validate_pure_csv.py \
  --graph youtube.txt outputs/pure_13/youtube.csv
```

For the thirteen-graph campaign:

```bash
bash scripts/run_pure_13.sh
```

The `pure` matrix compares ST, ET1, and ET2 with termination guidance disabled in each framework. The batch launcher validates an existing six-mode, five-block CSV before skipping it; an incomplete or inconsistent file is reported instead of silently reused.

## 5. Run the other manuscript ablations

The commands below use the pinned source bundle installed in Step 2. Each invokes its original study driver and writes its own generated outputs inside the ignored experiment workspace.

```bash
bash scripts/run_paper_ablations.sh candidate --runs 5 --timeout 1200
bash scripts/run_paper_ablations.sh result-cr --runs 5 --timeout 1200
bash scripts/run_paper_ablations.sh double-2x2 --runs 5 --timeout 1200
bash scripts/run_paper_ablations.sh six-mode --runs 5 --timeout 1200
bash scripts/run_paper_ablations.sh ips-native-baseline --runs 5 --timeout 1200
bash scripts/run_paper_ablations.sh ips-native-ablation --runs 5 --timeout 1200
```

See [EXPERIMENT_COVERAGE.md](EXPERIMENT_COVERAGE.md) for each experiment's source module, comparison factors, and reporting semantics. The native IPS count-aggregation comparison has a different output protocol from explicit enumeration; likewise, Single and Double internal search timer boundaries are not necessarily identical. Report within-study controlled comparisons rather than ranking raw search times across incompatible protocols.

## Reproduction notes

- Repeat counts and command-line switches are explicit in the commands and underlying launchers. The C++ sources and native build definitions are included, so experiments do not depend on precompiled binaries.
- The data archive SHA-256, each graph's SHA-256, and required source-bundle SHA-256 are pinned in the repository.
- Report elapsed times, compiler settings, CPU, memory limits, and mode configurations together. Timings will vary with hardware and operating conditions.
- Raw experimental CSVs and logs are created during reproduction under Git-ignored output locations; no historical development results are shipped with this artifact.
- The source modules adapt algorithms from ICDE 2024 MBET and SIGMOD 2026 IPS. See [SOURCE_ATTRIBUTION.md](SOURCE_ATTRIBUTION.md) for provenance and third-party reuse information.
